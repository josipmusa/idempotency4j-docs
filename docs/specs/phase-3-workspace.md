## Deviations from the playbook, and why

### 1. Starlight is mounted by id prefix, not by nesting the content directory

Starlight injects a root-level `[...slug]` route, so `src/content/docs/quickstart.md` would
serve at `/quickstart` and collide with the hand-built pages. The common workaround is to
nest the files one level deeper (`src/content/docs/docs/`), which contradicts the layout in
AGENTS.md and reads badly in every future path.

Instead `src/content.config.ts` passes a `generateId` to `docsLoader` that prefixes every id
with `docs/`. Files stay where AGENTS.md says they live and serve under `/docs`.
`index.md` becomes `/docs/`. The prefix also strips `01-` style ordering prefixes from
filenames, so the ~24 pages of phase 4 can be ordered on disk without it reaching the URL.

**Cost:** ids are generated by project code rather than by Starlight's default, so a future
Starlight upgrade that changes id semantics is a place to look first. Phase 7 should confirm
sidebar links, prev/next and search all resolve under the prefix when the real page set
exists - with one page they prove little.

### 2. The site's `/docs` landing page exists with one true sentence

Phase 4 owns copy. Starlight cannot build an empty collection, so
`src/content/docs/index.md` carries two accurate sentences and an HTML comment naming what
phase 4 replaces them with. It is short, not placeholder: nothing in it is invented, per the
never-invent rule.

### 3. Installed agent tooling is gitignored, not vendored

`npx skills experimental_install` and `npx impeccable install --project` write ~12MB across
`.agents/`, `.claude/skills/` and `.github/skills/` - three copies of the same tree,
dominated by a platform-specific `impeccable` binary and a 3.7MB font index. Committing them
would make the first commit of a documentation site 167 files of other people's tooling and
would bind the history to `darwin-arm64`.

They are treated as restorable dependencies: `skills-lock.json` pins the first set, the
restore commands are in AGENTS.md, and `.claude/agents/design-reviewer.md` - which comes
from the playbook template and is not installed - is committed.

**Cost:** a fresh clone needs the two install commands before the animation and taste skills
are available.

### 4. `spikes/screenshots/` is ignored except the palette renders

The playbook ignores the whole directory as throwaway. The six palette direction renders and
the locked light/dark pair are the rendered evidence D16 was decided from, and D16 reverses
an earlier decision, so they are kept.

### 5. `git init` ran with a repository-local identity

`user.email` and `user.name` are set on this repository only, at the owner's instruction,
because this project publishes under a different identity from the machine default.

## Known warning, not yet resolved

`npm run build` prints `The collection "i18n" does not exist or is empty.` Starlight looks
for the i18n collection on every build; the site is English-only by decision, so there is
nothing to put in it. Harmless, but it is a standing warning against the project's
no-warnings bar. Worth one attempt in phase 7.

## Review findings fixed in this phase

- **P1, home favicons hardcoded outside the base prefix.** `src/pages/index.astro` was still
  the Astro scaffold and requested `/favicon.svg` and `/favicon.ico`, which 404'd at every
  viewport - the exact failure shape AGENTS.md rule 1 names. Both now go through `href()`.
- **P2, empty docs sidebar rail.** `autogenerate` over a one-page collection rendered a
  blank 300px rail at 1440 and a mobile menu button that opened onto no navigation. The
  explicit `sidebar` config is removed until phase 4 lands the real page set; Starlight's
  default listing is honest at this size.
- **P2, the home route was the unmodified Astro scaffold**, titled "Astro" and linking
  nowhere. Replaced with a holding page: correct title and description from `src/consts.ts`,
  a link into `/docs` and to GitHub, `initial-scale=1` restored. No design tokens - phase 7
  owns the homepage and nothing here anticipates it.

Left for the phase that owns them: `?motion=reduce` (phase 8, with the first animation),
Starlight restyling (phase 7), the light/dark default (phase 7).
